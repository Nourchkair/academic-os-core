## Purpose

This course folder is both a human filing system and an AI-agent workspace. Original academic files remain preserved; generated summaries, dashboards, questions, and plans are navigation aids, not primary evidence.

## Folder purposes

- `00_INBOX/` — temporary, unclassified intake.
- `01_COURSE/` — course-wide operating files.
- `02_WEEKS/` — known week-specific material only.
- `03_ASSIGNMENTS/` — confirmed assignment workspaces.
- `04_EXAMS/` — confirmed exam information and preparation.
- `05_REFERENCE/` — course-wide textbooks, readings, data, and references.
- `06_KNOWLEDGE/` — source index, verification, research, history, and claims.
- `99_ARCHIVE/` — superseded operational material worth preserving.

## Intake procedure

For each new item in `00_INBOX/`:

1. Inspect the actual file, not only its filename.
2. Identify semester, course, source type, and component if possible.
3. Compare it with current authoritative material and detect new versions.
4. Preserve the original and avoid overwriting same-name files.
5. Move it only when classification is clear; otherwise leave it with an uncertainty note.
6. Update dependent context/status/schedule/assignment/exam/source/log files only when supported.
7. Check whether it reveals a Calendar event or change.
8. Verify the result.

## Sources and writing

Use the authority hierarchy in `../../ACADEMIC_OS_RULES.md`. Generated summaries and dashboards are not citation endpoints. For essays, follow instructions → rubric → overrides → original course sources → verified evidence/page numbers → permitted external research → outline → draft → review. Never fabricate quotations, page numbers, publication details, URLs, or DOIs.

## Calendar and communications

An authorized external agent may read selected calendar or forwarded academic communications after the student grants access through that agent. Academia OS does not connect to Calendar or Gmail. Record any agent-reported context and source in the local logs; calendar writes require confirmation and duplicate checks, and email must never be modified or sent by this workspace.

## Course-platform acquisition

If the student approves an external agent's course-platform workflow, that agent may use its own visible browser handoff. Manual import and watched folders work without browser access. The current browser workflow is limited to optional visible Chromium-family handoff; Firefox, Safari, and a browser companion are future adapters. Academia OS does not connect to Brightspace or another course portal. Any handoff is read-only: never enter or store passwords/MFA codes, read cookies, submit work, answer quizzes, post messages, or change settings. Accepted downloads enter this course's `00_INBOX`; the local processing lifecycle owns classification and verification.

## Standard commands

Recognize: `Process inbox`, `Course review`, `Weekly review`, `Study Week X`, `Prepare for [exam]`, `Start [assignment]`, `Check [assignment]`, and `What should I work on today?`.

## Version safety

Never casually overwrite personal notes, drafts, final submissions, graded work, or original professor material. Preserve sequential versions and use `99_ARCHIVE/` for clearly superseded operational material.
